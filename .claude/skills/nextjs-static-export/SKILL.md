# Next.js 16 static export: rules for this project

This site uses `output: "export"`. `next build` must produce a fully static `/out` folder. Anything that needs a request-time server will break the build.

Bundled docs for the installed version live in `node_modules/next/dist/docs/01-app/`. Read the relevant file when unsure; it overrides memory.

## Allowed
- Server Components (run at build time) and Client Components (`"use client"`).
- Dynamic routes **only with `generateStaticParams()`**, plus `export const dynamicParams = false`.
- `metadata` / `generateMetadata`, `sitemap.ts`, `robots.ts` (static), `opengraph-image` (static).
- `next/link`, `next/font`, `next/image` (images are `unoptimized`, so size them yourself).
- Route Handlers only as `GET` with `export const dynamic = 'force-static'`.

## Not allowed (will fail with static export)
Server Actions, `cookies()`, `headers()`, `draftMode()`, `redirects` / `rewrites` / `headers` in next.config, `proxy.ts` / middleware, ISR / `revalidate`, dynamic routes without `generateStaticParams`, `searchParams`-driven server rendering, the default image optimiser.
Forms (contact / book a call) are **front-end only** in this prototype: client-side validation plus a success state, no submit endpoint.

## Next 16 conventions
- `params` is a **Promise**: `const { slug } = await params`.
- Use the global type helpers `PageProps<'/blog/[slug]'>` and `LayoutProps<'/'>` (no import needed; generated by `next dev`, `next build` or `next typegen`).
- `next build` does not run lint. Run `npm run lint` separately.
- Turbopack is the default bundler.

## Dynamic route template
```tsx
// app/services/[slug]/page.tsx
import type { Metadata } from "next";
import { notFound } from "next/navigation";
import { services, getService } from "@/lib/services";

export const dynamicParams = false;

export function generateStaticParams() {
  return services.map((s) => ({ slug: s.slug }));
}

export async function generateMetadata(
  { params }: PageProps<"/services/[slug]">
): Promise<Metadata> {
  const { slug } = await params;
  const service = getService(slug);
  return service
    ? { title: service.title, description: service.summary }
    : {};
}

export default async function Page({ params }: PageProps<"/services/[slug]">) {
  const { slug } = await params;
  const service = getService(slug);
  if (!service) notFound();
  return <main>{/* ... */}</main>;
}
```

## Metadata
- The root layout defines `metadataBase`, `title: { default, template: "%s | <Company>" }`, a default description and Open Graph tags.
- Every page exports its own `title` and `description`, written for search intent (e.g. "Web Application Penetration Testing for SaaS & Fintech").
- Add JSON-LD (Organization, Service, Article) where useful, via a `<script type="application/ld+json">` in a Server Component.

## Links and assets
- Internal links use `<Link href="/services/web-application-penetration-testing/">`. Trailing slashes are fine; `trailingSlash: true` is set.
- Put static assets in `public/` and reference them as `/file.svg`. Prefer SVG for illustrations and icons.

## Verify
Run `npm run lint && npm run build`. The build output must list every route as `○ (Static)` or `● (SSG)`.
